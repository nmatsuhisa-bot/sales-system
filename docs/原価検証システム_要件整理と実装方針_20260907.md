## 0. 結論（サマリー）

| 論点 | 結論 |
|---|---|
| 現行 Excel の仕組み | 「単価マスタ（1ブック1コピー）」＋「型式別原価表（部位→明細行）」＋「歩留まり重量は DWG の注記から手転記」の3層構造。計算ロジックは単純（数量×単価の積み上げ）だが、**マスタが3ブックに複製**され、**名称文字列で VLOOKUP** しているため更新漏れ・表記ゆれに弱い |
| 実装方式 | **販売管理システム（sales-system-v2）内にモジュール追加**を推奨。部材マスタ・3階層BOM・発注実績単価・在庫移動・工数・標準販売価格が既に同一DBにあり、将来の在庫・仕入連動要件をそのまま満たせる。別システム化はマスタの二重管理になる |
| 新規に必要な要素 | ①単価の時点履歴 ②資材種別と単位換算（円/kg→円/m 等） ③「歩留まり重量行」「長さ行」「サブアセンブリ参照行」を扱える原価BOM ④原価計算エンジン ⑤シナリオ（what-if） ⑥帳票 |
| DWG 連携 | 図面の板取り注記 `W m×L m×t mm×7.85=xx.xxkg` は機械的に読める。Excel の歩留まり重量との一致率は **PLD 100% / BFQ 92% / BFR 81%**。板金明細の自動生成は現実的 |
| 受入基準 | Excel の計算値（BFR3X6 3,149,906円 / PLD5.5-2R52 112,043円 / BFQ7V 184,023円）を DB 取込後に再現できること |
| 決定事項（9/8 回答） | 加工費＝標準工数×時間単価（初期値 2,500 円/h、設定変更可）。値上想定倍率は標準原価から外しシミュレーション専用に。資材コードは **TECHS 品番**を採用し販売管理と同期。単価は**仕入先ごと**に持ち複数仕入先を比較。案件仕様差は同一商品として扱い**取引先単位の値引き調整**で吸収。塗料按分は製品ごと。並行運用中はスプレッドシートとマスタを同期。経費率・目標粗利率は保留（設定項目として用意） |

## 1. 添付資料の分析

### 1.1 Excel（原価表）の構造

3ブックとも同じ構造。**製品群ごとに1ブック、型式ごとに1シート**。

```
ブック（例: BFQ原価 2026.8.xlsx）
├─ 単価マスタシート（Sheet11 / 部品リストVLOOK用）    … 343〜439行
│   ├─ 上段: 鋼材単価表  鋼種×板厚×定尺 → 円/kg（2020.2 と 2025.9 の2時点）
│   └─ 下段: 部品リスト  「原価表上名称」をキーに 2020単価 / 2025.9単価 / 単価計算根拠 / 値上率
└─ 型式シート（BFQ3V / BFQ5V / BFQ7V / … / Qコンテナ）
    ├─ ヘッダー: 型式・作成日・合計・前時点比の値上率・部位別原価一覧・鋼材/購入外注の割合
    └─ 明細: 部位（天井/ホッパー/脚/…）ごとの行グループ
```

#### 明細行の種類（原価BOMの設計に直結する）

| 種別 | 例 | 数量の持ち方 | 単価の単位 | 備考 |
|---|---|---|---|---|
| A. 板金（歩留まり重量） | `正面板/3.2t` `ﾎﾞﾝﾃﾞ-2.3` | LA歩留まり重量 kg（`=117+74.27` のように枚数分を式で合算） | 円/kg | 重量は DWG 注記からの転記 |
| B. 形鋼・パイプ・ゴム（長さ） | `FB=平鋼 6×38 6000L` `SGP 40A` | 使用 m（`=1.47*(6+6+4+4)`） | 円/m | マスタ側で「円/kg × kg/本 ÷ m/本」に換算 |
| C. 面積材 | `ﾊﾟﾝﾁﾝｸﾞ-1.6-φ5-P8` | 使用 ㎡ | 円/㎡ | 「枚単価 ÷ (1.219×2.438)」で換算 |
| D. 購入品（個数） | ボルト・ナット・ベアリング・モータ・ノブ | 数量（`=12*2*2-2*2*2`） | 円/個 | 一部に **弊社品番（techs品番 208001038 等）** が併記 |
| E. 外注加工 | `扉蝶番60L-000001129/外注/メッキ` `外注/焼鈍` | 数量 | 円/個 | 図番＋工程で名称化 |
| F. 塗料 | `ﾆｭｰKRﾏﾘﾝ ｼﾙﾊﾞｰ 16K` ×0.1缶 | 缶の按分 | 円/缶 | 2026.7 に追記。工場1回＋現場1回 |
| G. サブアセンブリ参照 | `逆洗ﾀﾞﾝﾊﾟｰ 3型`×6 `TVS18.5-4M63E`×2 `RV30X80`×1 | 台数 × 別シートの合計 | — | ユニットを別シートで原価計算し参照 |
| H. 想定倍率 | I列「値上想定した倍率」1.15 | 単価に乗算 | — | 「値上していないボルトナットは15%値上想定」「フィルターは10%」 |

BFR3X6 シートの規模: 明細 338 行（うち歩留まり重量行 100、長さ・数量行 238）、部位 26。
PLD5.5-2R52: 27 行。BFQ7V: 112 行。

#### 単価マスタの実態

| 項目 | 事実 |
|---|---|
| 件数 | BFR ブック 343 / PLD 369 / BFQ 439（BFQ に 71 件追加分あり） |
| 3ブックの整合 | 共通 342 件のうち単価が食い違うのは 1 件（`点検窓/カイダック-3.0t*150*500`: 794 円 vs 496 円）。**コピー運用のため既に差異が発生**している |
| 単価の時点 | 列追加方式（2020.2 → 2022.3 → 2024.4 → 2025.9）。履歴として構造化されていない |
| 単価の根拠 | 「単価計算根拠」列に `(円/kg)×21.2kg/6.0m=(円/m)` 等の文字列。式そのものはセル数式に埋め込み |
| 仕入先 | 備考として「仕入先を大清からｲｼｸﾞﾛへ切り替えた為安価」等の記述のみ |
| 更新指示 | G1 セル「※更新する時は各シートにコピペしていってください」 |

#### 現行 Excel で確認された問題点

1. **表記ゆれによる原価漏れ**: BFR3X6 の `ﾕﾆｸﾛ平W-M10`（184個 ×2行）はマスタ側が `ﾕﾆｸﾛ丸W-M10` のため VLOOKUP が失敗し、`#VALUE!` となって小計から欠落している。
2. **マスタの複製**: 上記の単価差異 1 件は氷山の一角で、今後ブックが増えるほど乖離する。
3. **時点比較が手作業**: 「2024.4からの値上がり率」は前回値を別列に手コピーして算出している。
4. **数量根拠が式の中にしかない**: `=12*2*2-2*2*2` の意味（何を何個）は式を読まないと分からない。
5. **売価との対比がない**: 原価表単体で、販売価格（見積パターン）や粗利率は別管理。

### 1.2 DWG（歩留まり原価計算図）の構造

`dwg2dxf`（LibreDWG。既存の CAD 解析でも使用）で変換して解析した。

| 図面 | エンティティ | レイヤー | 板取り注記の件数 | Excel 重量との一致 |
|---|---|---|---|---|
| PLD5.5-2R52 | LINE 224 / ARC 205 / MTEXT 32 | `製作図` `0` | 10 | 10 / 10（100%） |
| BFQ7P-000 | LINE 3,900 / MTEXT 102 / TEXT 46 | `製作図` `0` `LEVEL002` | 25 | 23 / 25（92%） |
| BFR3X6 | LINE 7,822 / MTEXT 583 / INSERT 528 | `製作図` `0` `LEVEL001` ほか | 110 | 89 / 110（81%） |

図面に書かれている情報（MTEXT / TEXT）:

- **板取り注記**: `1.524m*1.4614m*2.3mm*7.85=40.2116kg`、切欠きありは `(1.524m*2.444m-0.554m*0.5756)*2.3mm*7.85=61.39kg`
- **鋼種・板厚・定尺**: `SPHC3.2t-5*10` `ボンデ2.3t-5*10` `SPCC1.2t-4*8` `パンチングφ5-1.6t-3*6`
- **部位名**: `天井` `ホッパー` `脚` `サイレンサー` `シェーキング` `空送ホッパー` `チェーンカバー` …
- **比重**: `鉄比重 7.85kg/cm3` `SUS304比重 7.93kg/cm3`
- **面積材**: `0.914m*1.092m=1.00㎡`

つまり **明細行種別 A（板金）はほぼ図面から生成可能**で、Excel はその転記＋購入品の追加である。
不一致分（BFR 21 件）は図面側の値を Excel で合算・丸めしているケースが主で、行単位に分解すれば追跡できる。

### 1.4 原価漏れの総点検（2026-09-08 追加）

3 ブックの全型式シート（BFR 1＋ユニット 3、PLD 10、BFQ 6）について、(a) 単価の VLOOKUP が失敗している行、(b) 原価が計算されているのに部位小計の SUM 範囲に含まれていない行、の 2 観点で機械点検した。

| ブック / シート | 内容 | 影響 |
|---|---|---|
| BFR3X6 | 入口ダクト φ500（321〜323 行）と φ425（347〜349 行）の組付けボルト・平W・袋ナット計 6 行が、小計 `SUM(J304:J318)` / `SUM(J328:J342)` の**範囲外**にある。うち `ﾕﾆｸﾛ平W-M10` 2 行はマスタ名が `丸W` のため `#VALUE!` | 約 5,800 円/台が合計から欠落（総額の 0.2%）。金額は小さいが「行を追加すると小計範囲から外れる」構造的な漏れ |
| RV30X80 ／ 逆洗3型 | 41〜53 行／50〜62 行に BFQ 天井部品（ノブ・天井吊り・セルプレートリング 等）の行が残っている。BFQ 用シートを流用した痕跡で、6 行は `#VALUE!` | 小計範囲外のため**合計への影響なし**。ただしシステム取込時に除外しないと誤った BOM になる |
| PLD 10 型式 | 該当なし | — |
| BFQ 6 型式 | 該当なし（スナップリング・フィルター・ポリ袋はヘッダーから直接参照しており合計に含まれる） | — |

システム化後はこの 2 観点（単価未解決・小計外）が検証ビュー（R1-8）で常時検出される。

## 2. 要件整理

### 2.1 ① 製品単位での資材利用状況・単価の検証

| ID | 要件 | 補足 |
|---|---|---|
| R1-1 | 資材マスタを一元化し、種別（鋼板/形鋼/パイプ/面積材/購入品/外注加工/塗料）と**単価単位**（kg/m/㎡/個/枚/缶）を持つ | 既存 `material_masters` を拡張 |
| R1-2 | 単価を**時点履歴**で持つ（有効開始日・単価・根拠式・出典・仕入先） | 「2025.9.17時点」のような列追加をやめる |
| R1-3 | 鋼材は「鋼種×板厚×定尺→円/kg」、形鋼は「円/kg×kg/本÷m/本→円/m」、面積材は「枚単価÷定尺面積→円/㎡」の**換算をマスタで定義**し、換算式を明示する | 現行の「単価計算根拠」列を構造化 |
| R1-4 | 製品→部位（ユニット）→明細行の原価BOM。明細行は 1.1 の A〜G の種別を区別し、**数量式と評価値の両方**を保持する。「値上想定倍率」は標準原価には持たない（回答 3） | 塗料の按分数量は製品ごとの明細行として持つ（回答 7） |
| R1-5 | 板金行は歩留まり重量の根拠（W×L×t×比重、切欠き、枚数）を保持し、DWG 注記からの取込に対応する | 1.2 参照 |
| R1-6 | サブアセンブリ（逆洗ダンパー、TVS、RV 等）は独立したユニットとして原価計算し、複数製品から参照できる | ブック間で共有できない現状を解消 |
| R1-7 | 任意の**単価時点**を指定して製品原価を計算し、部位別小計・鋼材/購入外注比率・前時点比を出す | 計算エンジン |
| R1-8 | 検証ビュー: 単価未登録・名称不一致・単価が古い品目・前回計算との差分・差分要因（単価差×数量／数量差×単価）を一覧化 | 現行の `#VALUE!` 漏れを検出 |
| R1-9 | 名称の別名（エイリアス）管理。Excel の「原価表上名称」の揺れを吸収して取込む | `ﾕﾆｸﾛ平W` と `ﾕﾆｸﾛ丸W` |
| R1-10 | 既存 3 ブック（BFR/PLD/BFQ、計 21 型式＋3 ユニット）の初期取込。1.4 の小計外の行・流用残骸行は取込時に警告し、確認のうえ除外／採用を選べる | 取込結果が 1.3 の値と一致すること |
| R1-11 | 資材コードは **TECHS 品番**（208001038 等）を正とする。TECHS 未採番の資材は仮コードを付与し、後で置換できる。販売管理側の部材マスタとも同一コードで同期する（回答 4） | 同期方式（CSV／API）は TECHS 側仕様の確認が必要 |
| R1-12 | 単価は**仕入先ごと**に履歴を持ち、同一資材を複数仕入先から仕入れる前提で「資材 × 仕入先」の単価比較ができる。標準原価に採用する単価は資材ごとに「採用仕入先」または「最安」を選べる（回答 5） | |
| R1-13 | 資材に対して**取引先単位の値引き調整**（加減算額または率、有効期間）を登録でき、調整がなければ素の単価を使う。案件仕様の差分（持永木材向け等）は同一商品として扱い、この調整で吸収する（回答 6） | 「取引先」は仕入先を第一に想定。顧客単位でも同じ表で扱える |
| R1-14 | 並行運用のため、資材マスタ・単価・BOM をスプレッドシート（Excel／Google スプレッドシート）と同期できる。取込・出力・差分検出の 3 機能（回答 9） | |

### 2.2 ② 販売単価シミュレーション

| ID | 要件 | 補足 |
|---|---|---|
| R2-1 | 製造原価 = 材料費（①）＋加工費（標準工数×時間単価）＋外注費＋経費率。工数は既存 `product_hours`（例: BFR3X6 = 240h）を利用。時間単価は**初期値 2,500 円/h** で設定画面から変更可（回答 1）。経費率・目標粗利率は設定項目として用意し、値は保留（回答 2） | 未設定の間は材料費＋加工費のみで表示 |

| R2-4 | シナリオの保存・比較（ベース vs シナリオ A/B） | |
| R2-5 | 型式横断の一覧（PLD 10 型式、BFQ 6 型式など）で原価・売価・粗利率を並べて比較 | |

## 3. 既存システムの流用可否

sales-system-v2（FastAPI + React + PostgreSQL）の現状:

| 既存テーブル／機能 | 内容 | 流用 |
|---|---|---|
| `material_masters` | 部材マスタ（コード・名称・単位・仕入先・LT） | ◎ 拡張して資材マスタに |
| `product_masters` / `unit_masters` / `product_unit_boms` / `unit_material_boms` | 製品→ユニット→部材の 3 階層 BOM | ◎ 原価BOMの骨格。明細行種別・数量式・重量根拠を追加 |
| `bom_items` | 旧 BOM（型式→部材） | △ 3階層に統合して廃止候補 |
| `material_purchase_orders` / `material_orders` | 発注書・明細（単価あり） | ◎ 実績単価の出典（F-1） |
| `material_stock_movements` | 部材在庫の入出庫 | ◎ F-2/F-4 |
| `product_hours` | 型式別標準工数 | ◎ R2-1 |
| `estimate_bfr_bodies` ほか見積パターン | 標準販売価格 | ◎ R2-2 |

## 4. 実装方針（方式 A）

### 4.1 データモデル（追加・拡張）

```
material_masters（拡張）  material_code は TECHS 品番を正とする（未採番は仮コード T-xxxx）
  + material_category   鋼板/形鋼/パイプ/面積材/購入品/外注加工/塗料/消耗品
  + price_unit          kg / m / m2 / 個 / 枚 / 缶
  + steel_grade, thickness_mm, stock_size    例: SPHC / 3.2 / 5*10
  + piece_weight_kg, piece_length_m          形鋼の換算用（21.2kg / 6.0m）
  + sheet_area_m2                            面積材の換算用（1.219×2.438）
  + density                                  7.85 / 7.93
  + code_source                              TECHS / 仮
  + preferred_supplier_id, price_policy      標準原価に採用する単価: 採用仕入先 / 最安

material_aliases（新規）          原価表上名称 → material_id（表記ゆれ吸収）
material_prices（新規）           material_id, supplier_id（必須。同一資材に複数仕入先）,
                                  effective_date, price, price_unit, basis_expr（根拠式）,
                                  source（手入力/見積/発注実績/スプレッドシート）, note
material_price_adjustments（新規） material_id, party_type（supplier/customer）, party_id,
                                  adjust_type（amount/percent）, value, effective_from/to, note
                                  … 該当が無ければ素の単価
cost_bom_lines（新規）            unit_id（部位/ユニット）, line_type（weight/length/area/count/
                                  subcontract/paint/subassembly）, material_id | sub_unit_id,
                                  qty_expr（"=117+74.27"）, qty, yield_basis_json
                                  （{W,L,t,density,pieces,cutouts}）, note, sort
cost_settings（新規）             labor_rate_per_hour（初期 2,500）, overhead_rate（保留=NULL）,
                                  target_margin_rate（保留=NULL）, 有効開始日つき
cost_calculations（新規）         product_id | unit_id, price_date, scenario_id,
                                  total, by_section_json, by_line_json, steel_ratio, computed_at
cost_scenarios（新規）            name, adjustments_json（鋼材+x% / 種別ごと想定倍率 / 品目上書き /
                                  仕入先切替 / 時間単価 / 経費率 / 目標粗利率）
```

製品（型式）は `product_masters`、部位とサブアセンブリは `unit_masters` に乗せる。
「BFR3X6 の天井」のような部位も `unit_type='部位'` のユニットとして扱えば、
逆洗ダンパーや TVS のような独立ユニットと同じ仕組みで参照できる。

### 4.2 原価計算エンジン

`backend/app/costing.py`（純粋関数。DB 非依存でテスト可能）

1. 製品 → ユニット → 明細行を再帰展開（サブアセンブリは台数を乗じて展開）
2. 各明細行の資材について、指定日以前で最新の `material_prices` を仕入先ごとに解決し、`price_policy`（採用仕入先／最安）で 1 本に絞る。`material_price_adjustments` に該当があれば加減算する
3. 単価単位へ換算（円/kg→円/m 等）し、`qty × price` を算出（想定倍率はシナリオでのみ乗算）
4. 部位別・種別（鋼材／購入外注）別に集計、前時点との差分を単価要因と数量要因に分解
5. シナリオ適用（一律%・品目上書き・工数レート・経費率・目標粗利）

**受入テスト**: 取込直後の計算結果が 1.3 の Excel 値（BFR3X6 3,149,906 / PLD5.5-2R52 112,043 / BFQ7V 184,023、および各ユニット）と一致すること。

### 4.3 取込（Excel / DWG）

- **Excel 取込**: 3 ブックの構造（マスタシートの列位置、型式シートの部位見出し・行種別判定）は本分析で確定済み。
  部位見出し＝A 列、重量行＝C 列が数値、長さ行＝D 列、数量行＝E 列、外注＝名称に `/外注/`、
  サブアセンブリ＝H 列が他シート参照。数式は `qty_expr` にそのまま保存し、値は評価済みの数値を保存する。
- **DWG 取込**: `dwg2dxf` → MTEXT 走査 → 正規表現 `(W)m*(L)m*(t)mm*(density)=(kg)` で板取り注記を抽出し、
  近傍の鋼種注記・部位注記と紐付けて板金行候補を生成。担当者が画面で確認・確定する運用（全自動にはしない）。
  作図標準ドラフトに「板取り注記は部位ブロック内に置く」「鋼種注記は `鋼種 板厚t-定尺` 形式」を追加提案する。

### 4.4 画面

| 画面 | 主な機能 |
|---|---|
| 資材マスタ（既存拡張） | 種別・単位・換算パラメータ・別名・仕入先別単価履歴・値引き調整のタブ。仕入先比較（A 社 vs B 社）。単価の一括改定（スプレッドシート同期） |
| 設定 | 時間単価（初期 2,500 円/h）・経費率・目標粗利率の有効開始日つき設定 |

| 検証 | 未登録・不一致・古い単価・前回差分の一覧。差分要因のドリルダウン |

### 6.4 本番導入手順（詳細）

**Step 1. コードを本番に反映する（開発側の作業）**

```bash
cd ~/sales-system-v2
git add .gitignore WORKLOG.md backend frontend docs
git commit -m "feat(costing): 製品原価検証モジュール（管理者専用）を追加"
git push origin main
```

push すると Render がバックエンド（Docker）とフロントエンドを自動で再デプロイする。5〜10 分待ち、
Render のダッシュボードで両サービスが「Live」になったことを確認する。
バックエンドの `/docs`（Swagger）を開き、タグ「製品原価検証」が並んでいれば反映済み。

**Step 2. 管理者ユーザーでログインする**

- 原価検証は `role = admin` のユーザーにしか表示されない。
- 自分のユーザーが admin でない場合は、「ユーザー管理」画面で自分のユーザーを開き、役割を **admin** にして保存する
  （ユーザー管理は既存のどのユーザーからも開ける）。
- 役割を変えたら **一度ログアウトして再ログイン**する（サイドバーはログイン時の情報で表示を決めている）。
- サイドバーの一番下に「製品原価検証」が出れば OK。一般ユーザーには出ない。

**Step 3. テーブルを作る（初回のみ）**

- 製品原価検証画面の右上「テーブル作成（初回）」を押す → 「原価検証テーブルを作成しました」と出る。
- これで cost_* の 8 テーブルが作られ、時間単価 2,500 円/h が設定に入る。既存テーブルは触らない。
- 2 回押しても壊れない（冪等）。

**Step 4. 原価表 Excel を取り込む**

「取込」タブで、次の順に 1 ブックずつ行う（同じ資材・同じ時点の単価がブック間で食い違う場合、先に取り込んだ値が残るため、順番を固定する）。

1. `K007-001_BFR3X6-2026.7.xlsx`
2. `PLD原価 2026.7.xlsx`
3. `BFQ原価 2026.8.xlsx`

各ブックで: ファイルを選ぶ → **プレビュー** → 表の「差」列を見る → **取込を確定**。

プレビューで差が出るのは次の 4 型式だけで、いずれも Excel 側の式の誤り（§6.3）。そのまま確定してよい。

| 型式 | 差 | 理由 |
|---|---|---|
| BFR3X6 | −140 円 | 小ネジ 1 行に 2020 年単価、RVｼｭｰﾄ/2.3t がマスタ未登録 |
| PLD2.2-2R54 | +4,119 円 | 塗料 3 行の単価が 5 円になっている |
| BFQ15 | −3,885 円 | セルプレートリングの式が重量を掛けていない |

「小計外の行も取り込む」のチェックは **外したまま**でよい（Excel の合計に入っていない予備行を除外する）。

**Step 5. 動作を確認する**

- 「製品原価表」タブで型式 `BFR3X6`、単価時点 `2025-09-17` を選んで **計算**。材料費 3,149,767 円・製造原価 3,749,767 円・粗利率 45.6% が出れば正常。
- 比較する時点に `2020-02-25` を入れて再計算すると、+32.7% と差分要因（単価要因／数量要因）が出る。
- 「Excel 出力」で原価表の xlsx が落ちる。
- 「検証」タブで「検証を実行」。取込直後は `ﾕﾆｸﾛ平W-M10` と `RVｼｭｰﾄ/2.3t` の 2 件が「単価未解決」として出る。

**Step 6. 未解決の 2 件を直す（例）**

- 「資材・単価」タブで `丸W-M10` を検索 → `ﾕﾆｸﾛ丸W-M10` を選ぶ → 別名に `ﾕﾆｸﾛ平W-M10` を追加。
- 同じく `SPHC-5*10 2.3t` を選び、別名に `RVｼｭｰﾄ/2.3t` を追加。
- 「製品原価表」で BFR3X6 を再計算し、「検証」で未解決が 0 になることを確認。

**Step 7. 運用の初期設定（決まり次第）**

- 「設定」タブ: 経費率・目標粗利率を登録（未設定の間は製造原価に経費が乗らず、必要売価も出ない）。
- 「資材・単価」タブ: 仮コード（T- で始まる）の資材に TECHS 品番を付ける。仕入先を選んで単価を追加すると、仕入先比較と値引き調整が使える。

## 付録: 解析メモ

- DWG → DXF 変換: `dwg2dxf`（LibreDWG 0.13 系）で 3 図面とも変換可。ASCII DXF。
- 図面のブロック名は工番付き（例: `210342AA1-持永木材`）。作図標準ドラフトの「工番をブロック名に入れない」に反する現状の実例。
- BFR3X6 図面には `PLD7.5-4R60` の文字が 1 件含まれる（流用痕跡の可能性）。
- BFQ の単価マスタには `ﾊﾟﾝﾁﾝｸﾞ-4*8φ5P8` と `φ8P12` の 2 種があり、BFR/PLD ブックには `φ8P12` 系のみ。面積材の品種はブックによって増減している。
