# 手配書の自動補完 仕様（2026-09-16 テスト実装）

案件登録と見積にある情報を、手配書の初期値として自動で入れる。
足りない項目は帳票画面で加筆・修正する（帳票画面の編集機能はすでに稼働中）。

## 1. 基本ルール

1. **一度保存した手配書は自動補完しない。** 保存済みの値をそのまま表示する。
   自動補完が効くのは「まだ作っていない手配書を開いたとき」だけ。
2. 自動補完した値は**画面でそのまま書き換えられる**。保存すると、以後はその値が正となる。
3. **読み取れない項目は空欄のままにする。** 推測で埋めない（日時・納品方法・返却方法など）。
4. 情報源の優先順位は次のとおり。

| 順位 | 情報源 | 主に取れるもの |
|---|---|---|
| 1 | 見積（子IDに紐づく最新の見積） | 納入先・受渡場所・注文主担当・営業担当・作成者・件名・明細・社内工数 |
| 2 | 案件（子ID） | 顧客名・代理店名・営業担当・出荷予定日・注番（子ID） |
| 3 | 納入先マスタ（案件の顧客IDで参照） | 住所・TEL |
| 4 | 当日日付 | 作成日 |

## 2. 帳票ごとの対応

### クレーン・作業車等 依頼書

| 欄 | 自動で入る値 |
|---|---|
| 現場名 | 見積.納入先 → 見積.注文主 → 案件.顧客名 → マスタ.会社名+工場名 |
| 住所 | 見積.受渡場所 → **マスタ.住所** |
| TEL | **マスタ.TEL** |
| 現場ご担当者 | 見積.注文主 御担当者 |
| 注番 | 子ID |
| 作成日 | 当日 |
| 担当 | 見積.営業担当 → 案件.営業担当 |
| 作成 | 見積.作成者 |
| **明細（機械名・重量仕様・使用期間）** | **見積の社内工数**のうち、レッカー種別が入っている行、または品名に クレーン／ユニック／レッカー／ラフター／高所／リフト／ゴンドラ を含む行。機械名＝レッカー種別（無ければ品名）、重量・仕様＝品名＋数量、使用期間＝案件の出荷予定日。最大6件 |

社内工数に該当がない場合は、見積明細から同じ語で拾う。それも無ければ明細は空。

### トラック手配 送り状

| 欄 | 自動で入る値 |
|---|---|
| 送り先・住所・TEL・ご担当 | クレーン依頼書と同じ（現場＝送り先とみなす） |
| 注番・作成日・担当・作成 | 同上 |
| **積込内容** | **見積明細の機械本体行**（工事・据付・試運転・運搬・設計・諸経費などの役務行は除外）を最大8件まで「、」で連結。数量が2以上なら数量も付ける |
| 到着日 | 案件の出荷予定日 |
| 車種・積込①〜③・時間 | 空欄（手配時に記入） |

原紙は「1明細＝トラック1台」のため、初期値は1台分。台数が増える場合は画面の「明細を追加」で増やす。

### 排風機 注文確認書（PL／BFQ／FS の3様式）

原紙「排風機2011年～.xlsx」の BFQ注文確認書・FS注文確認書・PL注文確認書に合わせて、
1つの帳票で3様式を出し分ける。様式は見積明細から自動判定する。

| 様式 | 対象製品 | 判定条件（見積明細の品名・仕様） |
|---|---|---|
| BFQ | 小型バグフィルター集塵機 | `BFQ` / 小型バグ（小型ﾊﾞｸﾞ） |
| FS | ファンシュレッダー | `FS3` のような FS+数字 / ファンシュレッダ / 粉砕機 |
| PL | プレートファン | 上記以外（既定） |

共通部（宛先・受注No.・御確認印・ユーザー名／住所／TEL・出荷先／住所／TEL・出荷日・運送方法・
指定色・色番号・備考・営業／作成）は3様式とも同じ。仕様欄が次のように変わる。

| 様式 | 仕様欄の項目 |
|---|---|
| PL・FS | 名称／駆動方式／製造No.、型式／仕様／メーカ、周波数／動力(V)／制御(V)、モータ(kW・P・屋内外・フランジ型)／備考、仕様(屋内・屋外)、吸排気口(吸φ・排φ・合フランジ)、スイッチ(モータブレーカ・制御盤) |
| BFQ | 名称／型式／製造No.、周波数／動力(V)／制御(V)、排風機(標準・型式・メーカ)、モータ／備考、スイッチ(モータブレーカ・シェーカー用押ボタン・制御盤)、シェーカ(有無・手動/電動・取付位置)、袋受／ホッパー(種別・サイズ・空送・Qコンテナ・フレコン受け)、ロータリーバルブ(標準・特殊)、フィルター(サイズ・本数) |

挨拶文と運送方法の注記も様式ごとに変わる（BFQのみ「井上手配」を含む）。

**様式の切り替え**：編集画面の上部に「様式: PL」と出る。クリックで PL→BFQ→FS と切り替わり、
「保存して再表示」を押すとその様式で開き直す。印刷・PDFには様式欄は出ない。

**BFQ様式で見積から入る値**：型式（BFQ10V 等）、排風機の型式（spec_json の fan_model）、
シェーカの有無・手動/電動・取付位置（shaker_position）、ロータリーバルブ（RV25×40 等）、
制御盤の有無（switch）。フィルターのサイズ・本数、袋受／ホッパーの内容は見積に無いため空欄。

### 排風機 注文確認書／ファン作業指示書（共通の補完）

| 欄 | 自動で入る値 |
|---|---|
| ご使用者・お届け先・住所・TEL・ご担当 | 見積の納入先／受渡場所、マスタの住所・TEL |
| 出荷日 | 案件の出荷日 → 出荷予定日 |
| 型式 | 見積明細の品名から読み取り（PL/RT系） → **明細 spec_json の fan_model** |
| 製品名 | 明細の品名に「ターボファン」「プレートファン」が含まれればそれを採用（既定はプレートファン） |
| **周波数・電圧** | **明細 spec_json の hz / voltage**（BFQパターン選択で保存される値） |
| モータ出力・極数・吸込口径・吐出口径 | 見積明細の品名・仕様から読み取り |
| 注文主（作業指示書） | 案件.代理店名 → 見積.注文主 |
| 用途・仕様（作業指示書） | 見積.件名 → 案件名 |

### 宿泊予約票

| 欄 | 自動で入る値 |
|---|---|
| 現場名 | 見積.納入先 → 案件.顧客名 |
| 住所 | 見積.受渡場所 → マスタ.住所 |
| 宿泊先の明細 | 空欄（都度手配のため） |

### 見積管理から作る帳票（ファン作業指示書・ファン検査記録書）

| 欄 | 自動で入る値 |
|---|---|
| 発行日 | 見積.見積日 |
| 営業担当／作成 | 見積.営業担当／見積.作成者 |
| 型式 | **ファンの明細**（spec_json の fan_model → 品名の PL/RT/TVS 系）。無ければバグフィルター本体の型式 |
| 注文主・受注番号・納入先 | 見積.注文主／子ID／見積.納入先 |
| 用途.仕様 | 見積.件名（無ければ型式） |
| 出荷日 | 案件の出荷日 → 出荷予定日 |
| モータ 出力(kW) | ファン明細の spec_json.kw → 品名の「15kw」等 |
| モータ 極数 | 品名・仕様の「4P」等 |
| モータ 周波数・電圧 | 明細 spec_json の hz / voltage |
| モータ 屋内外・取付 | ファン明細の仕様に「屋外」「屋内」「フランジ」「脚取」があれば採用 |
| 吸口テーパ・出口角丸 | ファン明細の「φ380」等（1つ目＝吸口、2つ目＝出口） |
| 想定性能 風量 | 明細 spec_json の airflow |
| 軸受・プーリ・回転数・振動値・チェックリスト | 空欄（製作時に記入） |

### 見積管理から作る帳票（制御盤作業指示書）

| 欄 | 自動で入る値 |
|---|---|
| 受No.・納入先・注文主・担当 | 子ID／見積.納入先／見積.注文主／見積.営業担当 |
| 工場 | **納入先マスタの工場名**（案件の顧客IDで参照） |
| 名称 | 明細の「制御盤」の品名 |
| 概要 | 見積.件名 |
| 仕様 | 制御盤明細の仕様 |
| 周波数・動力(V) | 明細 spec_json の hz / voltage（200/380/400/415/440V を選択状態にする） |
| 操作SW | 明細 spec_json の switch（「制御盤」そのものは入れない） |
| 火花探知器・パトライト | 該当する明細があれば品名 |
| 見積金額 | 制御盤明細の金額 |
| **負荷一覧（名称・容量・台数）** | 見積明細のうち**モータを持つ品目**を最大15件。容量は spec_json.kw → 品名の「0.2kW」等から読む。制御盤・ダクト・フィルター・工事などの行は除外 |
| 操作回路(V)・指定色・架台・サイズ・電子図番 | 空欄（設計時に記入） |

## 3. 会社名の照合

納入先マスタは案件の**顧客ID**で引く。顧客IDが未設定の場合だけ会社名で照合する。
照合時は次を同一とみなす。

- 全角／半角（`ｾｲﾎｸ` と `セイホク`）
- 大文字／小文字
- 法人格の表記（`株式会社`・`(株)`の有無）
- 空白・中黒・ハイフン・括弧

## 4. 現状の制約（データ側の課題）

- **納入先マスタに住所・TELが未登録**（2026-09-16時点で9件すべて空）。このため住所・TELの自動補完は、マスタを整備するまで空欄のままになる。
- 見積の**社内工数を登録していない見積が多い**。登録があれば、クレーン依頼書の明細がそのまま埋まる。
- パターン選択（BFQ/BFR）を使わずに手入力した明細は `spec_json` が無いため、周波数・電圧は読み取れない。
